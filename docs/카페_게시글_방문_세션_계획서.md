# 카페 게시글 방문 세션 기능 계획서

| 항목 | 값 |
|------|-----|
| **제목** | 카페 게시글 방문 세션 기능 계획서 |
| **버전** | 1.3.28 (`version.txt` 참조) |
| **일시** | 2026-05-20 |

본 문서는 **상단 헤더 5번째 항목**으로 둘 **게시글 열람(조회 카운팅 가능한 브라우저 방문)** 계열 기능의 목표·범위·구현 순서를 정리합니다. 코드 반영 여부와 무관한 **설계 초안**입니다.

---

## 1. 목적

- **여러 로그인 ID**를 설정해 두었다가, **무작위 수십 초 간격**으로 순환하며 카페 **게시글 상세 URL**을 실제 브라우저로 여는 세션을 돌린다.
- 패턴은 **천천히·점진적**으로 두고, **일·시간대 상한** 등 안전 장치를 UI·정책으로 넣을 수 있게 한다.

---

## 2. UI·네비게이션

| 항목 | 내용 |
|------|------|
| 헤더 | `app/utils/streamlit_top_nav.py`의 `_NAV_PAGE_LINKS`를 **4→5항목** 확장 (`st.columns(4)`→`5`) |
| 새 페이지 | `pages/05_*.py` (파일명·표시 라벨은 확정 필요. 예: **「카페 방문」**, **「게시글 열람」**) |
| `active` 키 | 기존 `app`/`event`/`papers`/`commenter`에 새 키 1종 추가 |

---

## 3. 기능 구간(MVP → 확장)

### 3.1 1차(MVP)

1. **대상 URL** — 줄 단위 또는 표로 여러 게시글 주소 입력.
2. **계정 풀** — 다수 ID/PW(또는 로그인 전략 확정 후 프로필·세션 재사용 옵션). **저장 위치는 로컬 설정 전용**, 저장소 미커밋 원칙은 기존 `user_settings.json` 계열과 동일.
3. **실행** — 순차 처리 권장: 브라우저 1개, 계정마다 로그인(또는 세션 확인) → 글 순회 → **페이지 로드 후 수 초~수십 초 랜덤 체류**(선택적으로 가벼운 스크롤) → 다음 글·다음 계정까지 **간격 무작위**.
4. **제어** — 시작/중지, 진행 로그(계정은 마스킹 가능).

### 3.2 2차 이후

- 동일 글·동일 계정 **재방문 쿨다운**.
- 허용 **시간대 창**(예: 09:00~23:00)만 실행.
- **일일 회차·페이지 수 한도**, 로컬 SQLite로 이력·집계(선택).

## 5. 고지·리스크

- 네이버·카페 **이용약관·운영 정책**, 비정상 트래픽에 대한 **제재**(계정/IP/카페) 가능성은 제품 안내 문구에 **중립적으로 명시**하는 것을 권장한다.
- “조회수 상승”을 **항상 또는 일정하게 보장한다는 표현은 피하고**, 서버·통계 처리 방식에 따라 카운터 반영 여부를 약속하지 않는다.

---

## 6. 구현 순서(권장)

1. `pages/05_*.py` 스켈레톤 + 헤더 5번째 연결만 반영한다.
2. 설정 스키마(계정 목록, URL, 딜레이 최소·최대, 일 한도 초안)를 정의한다.
3. **단일 계정·단일 URL** 방문 프로토타입으로 동작 검증한다.
4. 계정 순환·랜덤 간격·중지 처리를 붙인다.
5. 이력 DB·문서(`docs/기능명세서.md`, `CHANGELOG.md`)는 릴리스 단위로 동기화한다.

## 7. 미정 사항

- 메뉴 한글 표기 최종명, 내부 세션 키(`active`) 영어 slug.
- 계정별 Chrome **프로필 디렉터리** 분리 여부(로그인 유지 vs 매번 로그인).
- 동시 브라우저 다중 창 지원 여부(MVP에서는 비권장).
